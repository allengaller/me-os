# 03 方法 —— 个人 IP 的可执行系统

> 逻辑与哲学回答「为什么」，方法回答「怎么做、按什么标准做」。
> 本层是五个子系统的集合：定位 / 内容 / 田野调查 / 分发增长 / 复盘迭代。
> 每套方法都直接对应品牌蓝本（DESIGN.md）与品牌控制台（Console）的落地环节。

---

## 1. 五套方法全景

```
定位 → 内容 → 田野 → 分发 → 复盘
 │      │       │      │      └─ 5. 复盘迭代（每期/月/季）
 │      │       │      └─ 4. 分发与增长（平台矩阵 + 北极星/KPI）
 │      │       └─ 3. 田野调查（内容主线的一手供给系统）
 │      └─ 2. 内容方法（支柱 + 选题 + 公式 + 一鱼多吃）
 └─ 1. 定位方法（黄金圈 + 定位陈述 + 原型人格 + 差异表）
```

| 方法 | 解决 | 核心输出物 |
|---|---|---|
| 定位方法 | 我是谁、为谁、不同在哪 | 定位陈述、原型人格、差异化表 |
| 内容方法 | 做什么、按什么标准做 | 内容支柱、选题漏斗、内容公式、检查清单 |
| 田野调查方法 | 一手反馈如何稳定产出 | 田野流程 SOP、同意清单、访谈提纲 |
| 分发与增长方法 | 内容如何被看见、被记住 | 平台适配表、渠道矩阵、北极星与 KPI |
| 复盘与迭代方法 | 如何持续变好 | reviewNote、月度/季度复盘模板 |

## 3. 方法使用的三条纪律

1. **方法服务于人，不服务于流程**：标准是「质量的下限」，不是「限制的枷锁」；
   现场情况优先时，允许偏离，但复盘时必须说明「这次为什么偏离」。
2. **方法要固化成工具**：所有方法最终应沉淀进品牌控制台
   （BrandProfile、ContentItem、分发矩阵、复盘区——见 Console 设计文档），
   让执行不依赖记忆。
3. **方法有保质期**：半年内未使用/未验证的方法，要么重新检验，要么删除——
   方法库存的理念跟内容库存一样：重质不重量。
