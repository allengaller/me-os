## 2. 架构决定

**排除项：保留 Prisma + 镜像部署。** 这条最省事（19 个 Fastify 模块基本不动），但没有直连串 Prisma 就起不来，`image` 运行时也就没意义了。若日后控制台暴露 PG 连接串可重议。

**选定：**

1. `apps/web` 走 **static 部署** → CDN，手机用 `https://<id>.meoo.fun` 访问。
2. 数据层用 **supabase-js 直连 + RLS**。
3. 特权逻辑（LLM、连接器代收）进 **Deno Edge Function**，`SERVICE_ROLE_KEY` 只存在这一层。
4. `packages/api` 那 19 个 Fastify 模块**退役**，不逐个移植。
5. `localDB.ts`（1695 行）保留价值：离线缓存 + 它本身就是「URL 路径 → 表/过滤条件」的现成规格书，写新适配器时照它抄。

**接入点是现成的**：`apps/web/src/lib/api.ts:286` 已经在 `localDBAdapter | remoteApi` 之间二选一，且 `LocalDBAdapter` 接口只有 6 个方法（`get/post/patch/delete/request/handleAuth`）。加第三个 `supabaseAdapter` 实现同一接口即可，页面层零改动。`main.tsx:14` 的 `useLocalMode ? HashRouter : BrowserRouter` 同理，改成 static 部署恒用 HashRouter。

## 3. 类型与命名转换规则

| Prisma/SQLite | PostgreSQL | 说明 |
|---|---|---|
| `String` | `text` | 主键保留已生成的 uuid 值，新行 default 换 `gen_random_uuid()::text` |
| `Int` | `integer` | |
| `Float` | `double precision` | |
| `Boolean` | `boolean` | |
| `DateTime`（实为 integer 毫秒） | `timestamptz` | **必须 `to_timestamp(x::bigint / 1000.0)`**。直接 cast 会得到 1970 年附近的垃圾值且不报错，这是本次迁移最容易踩的坑 |
| 7 个 JSON-in-text 列 | `jsonb` | `MeLogEntry.payload`、`MeLogSource.config`、`MeLogSkill.config`、`MeLogRun.stats`、`MeLogRun.entryIds`、`Subscription.config`、`PeriodicReview.dataSummary`。转 jsonb 后 PG 可直接查内部字段，是白赚的能力 |
| 5 个逗号分隔列 | `text[]` + GIN 索引 | `InsightNote.tags`、`MeLogEntry.tags`、`Contact.tags`、`ContentItem.tags`、`BrandProfile.personaTags` |

- 表名 PascalCase → snake_case（`MeLogEntry` → `melog_entry`），PostgREST 惯例；列名同样转 snake_case。
- **不加 CHECK / enum**。`status`/`priority` 这类字段虽然注释里写了取值域，但历史数据可能有违规值，加了会让导入中途失败。先导入，再 `SELECT DISTINCT` 审计一轮后决定。
- 8 处 `isMock`（Topic、BrandProfile、BrandPillar、PlatformChannel、ContentItem、ContentDistribution、Work、MetricSnapshot）在真库里语义已失效——云上只放你自己的数据。建议保留列但全置 false，别在云库跑 `seed.ts` / `seed-brand.ts`。

## 4. RLS 与认证

- 除 `app_user` 外每张表都有 `userId`，统一策略：`USING (user_id = auth.uid())`，`WITH CHECK` 同条件。策略名用英文 snake_case（平台规则：不带引号、不用中文）。
- 现在是 bcrypt + Fastify 自签 JWT，**不能沿用**。Supabase Auth 的用户在 `auth.users`，`auth.uid()` 是新 uuid，和旧 `User.id` 不同源 → 迁移时选定一个主用户，把 37 张表的 `user_id` 全部重写成它的 uid（单用户系统，这步是一次性 SQL）。
- `meoo cloud enable-register-login` 会触发云服务重启，**必须放在所有迁移和代码变更之后**（平台幂等规则）。
- `SUPABASE_SERVICE_ROLE_KEY` 绕过 RLS。它只应出现在 `meoo secrets set` 里，绝不能进前端代码、`.env`、或仓库——`.env` 已在 `.gitignore` 内，保持住。
- 现在前端有 `VITE_SKIP_AUTH` 和 `import.meta.env.DEV` 两条绕过（`App.tsx:28`、`Landing.tsx:13`）。公网地址上线前必须确认二者在生产构建里为假，否则手机访问等于无登录。

## 5. melog 的三处特判

- `scheduler.ts:85` 用进程内 `setInterval`。static 部署无常驻进程，**这条路没有家**。降级方案：`MeLogSchedule` 表照旧存，触发点改到前端（打开应用时检查 `nextRunAt` 是否过期并调 Edge Function）。真正的 cron 要另找平台能力，待查。
- `llm.ts` 已是 OpenAI 兼容 base URL（`MELOG_LLM_BASE_URL`，注释举例 deepseek / qwen-plus），Meoo 模型表里 `deepseek-v3.2`、`qwen3.6-plus` 都在 → 迁到 Edge Function 顺。注意 `MEOO_PROJECT_API_KEY` 只能在 Edge Function 侧用。
- `capture.ts` 与 `packages/connectors`（`melog-connector` CLI）现在写本地 SQLite。改成 POST 到 Edge Function，由它用 service_role 落库。这也是手机/其他设备往你库里灌数据的唯一正门。

## 6. 备份策略（"GitHub 作为备份"的具体落法）

- **代码仓库不存生活数据。** 现在这份 `meos.db` 只有 244 条 melog，但它会长大，且是隐私本体。
- 本机：`scripts/backup-db.sh`，保留最近 30 份（已生效）。
- 云上：**不能 `pg_dump`**（无直连）。可用路径是逐表 `meoo --json db query --project <id> "SELECT jsonb_agg(t) FROM (...)"` → 文本 dump。建议 dump 落到**另一个 private 数据仓库**，而不是本仓库——因为你后面要「抽取功能到新 public repo」，如果生活数据进了代码仓的 git history，抽取时很容易连带出去。
- 注意：SQL dump 不含 Supabase Storage 桶里的文件。目前没用 Storage，将来放图片附件时要单独备份。
- 明确不指望平台快照：计量项叫 `supabase_disk_snapshot` 说明平台侧有快照概念，但**没有对外的快照恢复命令**，`meoo deploy` 也不回滚数据。备份责任在你。

5. `auth.uid()` 在本实例的定义就是 `coalesce(nullif(current_setting('request.jwt.claim.sub',true),''), (nullif(current_setting('request.jwt.claims',true),'')::jsonb->>'sub'))::uuid`。策略统一写成 `"<col>" = auth.uid()::text`（我们的 id 是 text 不是 uuid，必须 cast）。

**两条踩坑记录（都会再遇到）**

- `meoo db migrate` 失败时一律报 `CLOUD_NOT_ENABLED / 请先执行 meoo cloud enable`，**与云服务状态无关**。我先后误判为「CLI 扫 `auth` 子串」和「`DO $$` 被按分号切坏」，两者都错：真实原因分别是列名写错、以及 `DO` 块本身没问题。用 `meoo --json db migrate` 才拿得到干净的成功/失败信号；定位方式是逐段二分。**结论：任何 migrate 失败，先 `--json` 再看真实返回，别信 hint。**
- 37 表 DDL 一次过没问题（37 KB）；`meoo db migrate` 只接受 `--sql`，长 SQL 用 `--sql "$(cat f.sql)"` 传是可行的。

**§7 P2 的前提被数据清点推翻**

### 发现并记录的平台约束

1. **Meoo 实例不支持公开注册**：`/auth/v1/signup` 返回 400 空正文。管理员通过 `/auth/v1/admin/users` 建账号，密码由管理员设置。
2. **本地 dev 登录被 Tengine 挡**：`POST /sb-api/auth/v1/token` 在 localhost 被 Tengine 网关返回 403（直连实例 200 正常）。**生产环境正常**。这是平台安全策略——本地 dev 需要通过 `VITE_USE_REMOTE=1` 走 Fastify 后端（或忽略本地登录，用生产 URL 测试）。
3. **`meoo deploy` 需要从 `apps/web/` 跑**（或配置 `--project` 指向有 `dist/` 的目录）。根目录跑会报"未找到构建产物目录"。
4. **根目录 `src/supabase/` 是 meoo migrate 的副产物**：每次 `db migrate` 都会重新生成。已加入 `.gitignore: /src/`，手维护版本在 `apps/web/src/supabase/`。
5. **`order` 列不是所有表都有**：`reflections`、`visions` 等没有 `order` 列。统一用 `createdAt desc` 排序更健壮。
