# 06-5 Build in Public 流派：过程即产品

> 世界观：**把构建过程公开，让每一步都被检验——公开不是暴露，是信用积累的最快路径。
> 过程不可伪造，结果可以；晒过程的创作者永远比晒结果的稀缺。**
> 代表：swyx / levelsio / Marc Lou / Gergely Orosz / Adam Wathan

---

## 1. 核心思维逻辑（六条）

### L1 Learn in Public：把学习过程变成公共资产
- **人物**：swyx（Shawn Wang，"Learn In Public" 2018 年长文）
- **逻辑**：学习的复利来自输出：写笔记、发帖、演讲、开源——每一样都在
  积累「可被搜索的个人资产」；网络反过来成为你的反馈回路与机会入口。
  存在空白感，但「如果你没有因为不懂而跌倒，你就没有学得够多」。
- **对 IP 的推论**：本 IP 是 Learn in Public 的「田野版」——每一次调教实验、
  每一场田野都写成公开记录；空白与失败同样发布（调教日志支柱）。

### L2 Process is Product：过程即产品
- **人物**：levelsio（Pieter Levels，独立开发者，公开收入面板）
- **逻辑**：观众/客户真正参与的是「跟你一起走完从 0 到 1」的过程；
  产品最终形态只是过程的高潮。收入、失败、迭代全部公开，
  透明本身成为产品特色（levelsio 以「24 小时建站挑战」与公开 MRR 著称）。
- **对 IP 的推论**：田野调查的「过程」（约访、踩坑、打脸）与结果同等重要——
  把「被拒三次才约到受访者」剪进正片，比只放访谈全程更有价值。

### L3 公开收入与数据：透明是信任策略
- **人物**：Marc Lou（独立开发者，公开收入面板）；levelsio
- **逻辑**：公开收入/流量数据，把自己置于「经得起检验」的位置；
  数据透明带来三类红利：信任、监督（不敢懈怠）、同行资源。
- **对 IP 的推论**：调教数据、内容数据季度公开；收入按需公开
  （财务敏感边界：01-逻辑/4 与 02-哲学/4 保密区）。

### L4 专家通讯：垂直深度的订阅生意
- **人物**：Gergely Orosz（The Pragmatic Engineer newsletter，年收入达七位数美元的 Substack 头部通讯，自述与多家媒体报道）
- **逻辑**：工程师 IP 的最优路径之一 = 深度垂直 + 订阅制——
  内容极窄（软件工程实务）但极深，企业为其人才订阅付费。
- **对 IP 的推论**：「田野通讯」订阅制试点（06-3 已列）的参照——
  本 IP 的垂直深度在「行业真实反馈 + 极致方法」，订阅信源成立
  （收口：私域沉淀环）。

### L5 高频小步发布：用发布节奏对抗不确定性
- **人物**：Marc Lou、levelsio 及独立开发者社区
- **逻辑**：与其一年憋一个大的，不如每月发一个小的——
  高频发布让每一次失败的代价变小，让市场反馈及时进来。
- **对 IP 的推论**：田野项目拆成「多期连续剧」而非「年度大片」；
  每期都有独立交付点（对应 03-方法/2 节奏基线）。

### L6 公开的边界感：什么都公开 = 什么都没公开
- **人物**：BIP 社区反思（swyx、levelsio 等实践中反复讨论）
- **逻辑**：公开要有「留白」：保留未公开的深度，让公开物具有可辨识的
  形状；同时保护隐私与商业秘密。公开的稀缺性来自选择性。
- **对 IP 的推论**：公开区/保密区二分法（02-哲学/4 §2）已内化——
  方法论与数据公开，隐私与敏感细节保密。

## 3. 批判与警戒（不学什么）

| 危险形态 | 问题 | 警戒 |
|---|---|---|
| 裸奔公开 | 隐私/安全暴露 | 保密区清单先行 |
| 表演式公开 | 公开的是人设不是过程 | 数据可复核才叫公开 |
| 公开焦虑 | 数据差不敢发 | 差数据 + 复盘 = 信任加分（02-哲学/4） |
| 收入炫耀 | 只晒收入不晒方法 | 收入公开要带可学习方法 |
| 为公开而公开 | 隐私与商业信息的误伤 | 拿不准不公开，先问「主人是谁」 |
