## 三条记录通道

1. **表单 CRUD**（18/19 个模块）— 稳但慢，适合低频、结构化数据
2. **一键 / 快捷**（今日页快速待办、习惯打卡）— 入口聚合好，只覆盖待办与习惯
3. **自然语言 / 批量**（口述打卡、`/ingest`、MCP）— 目前只有 MeLog 具备

## Chrome 扩展（快速待办直写）

> 2026-09-12 从「只跳转」升级为「可直写」：popup 输入待办回车即调 `POST /api/todos`。

### 部署步骤

1. 启动 MeOS：`./scripts/meos start`（前端 :3000，后端 :3001；`./dev.sh` 等价但会顺带跑 bootstrap）
2. Chrome → `chrome://extensions` → 开发者模式 → 「加载已解压的扩展程序」→ 选择 `apps/chrome-extension/`
3. 先打开一次 `http://localhost:3000` 并登录（扩展从该页面 localStorage 读 token，键 `meos-auth`）
4. 任意页面点扩展图标 → 输入待办回车 → 直写；失败时按提示检查后端或登录状态

机制：popup 向活动标签页发送 `GET_MEOS_TOKEN`（content script 读取页面 localStorage，无需在扩展里登录）；若活动标签不是 MeOS，回退读 `chrome.storage.local` 的 `meos_token`。生产域名 `meos.app` 已在 manifest 主机权限与 content_scripts 匹配中。

### 实测结果（2026-09-12）

- ✅ 语法与 manifest 校验通过（`node --check` + JSON 解析）
- ✅ token 通道：登录后页面 localStorage 确实存在 `meos-auth`（zustand persist 结构 `{state:{token}}`），content script 读取逻辑与之对应
- ✅ API 通道：`POST /api/todos` + Bearer 头，后端 CORS `origin: true` 允许扩展来源
- ⚠️ popup 完整点击路径（加载 unpacked 后输入→提交）需手工在 Chrome 验证一次
