## 1. 总纲：起号的第一性认知

### 1.1 起号的定义

**起号 = 让平台与目标受众在最短时间内，完成对你「是谁、给谁看、有什么价值」的识别与信任积累。**

起号成功 ≠ 单条爆款；爆款是起号的加速器，不是起号本身。一个号真正「起来」的标志是：

1. **标签清晰**：平台能把你推给正确的人（垂直度达标）；
2. **转化稳定**：单条内容 → 主页 → 关注，这条转化链跑通；
3. **供给有下限**：你已证明自己能以可持续的频率产出达标内容。

### 1.2 三条底层规律（为什么这套方法论成立）

1. **平台不是玄学，是「数据收集 + 反馈循环」系统。** 算法没有立场，它只做三件事：把内容推给一批试探人群 → 观察反馈（完播/互动/关注）→ 决定是否扩大流量池。起号的本质是**配合算法完成它对你的「模型训练」**：给它足量的、标签一致的内容样本，让它快速学会「你是谁、该推给谁」。
2. **冷启动期的第一优先是「数据信号」，不是「内容质量自评」。** 你自认为的好内容 ≠ 系统认可的好内容。起号期的目标是**收集足够多的真实反馈**（播放、完播、互动、粉丝），用它们校准你的内容判断。
3. **涨粉 = 曝光 × 转化率，两者都有杠杆。** 曝光靠算法（标签、垂直度、完播），转化靠主页（头像/简介/置顶/简介里的一行价值主张）。只优化内容不优化主页，等于前面导流后面漏水。

### 1.3 起号的阶段模型（本手册的骨架）

| 阶段 | 时间 | 核心任务 | 成功标志 |
|---|---|---|---|
| Phase 0 准备 | 发布前 1–2 周 | 定位校验、对标调研、账号装修、弹药库 | 弹药 ≥ 30 条选题；装修完成；主阵地选定 |
| Phase 1 冷启动 | 0–90 天 | 打标签、测反馈、建转化链 | 出现 1–3 条跑出均值 5–10 倍的内容；涨粉率/主页转化达标（§8） |
| Phase 2 成长期 | 90 天 – 6 个月 | 复制验证过的模型、系列化、稳定频率 | 周更节奏稳定；单条均值持续抬升；出现小爆款 |
| Phase 3 稳定期 | 6 个月 + | 稳定供给、矩阵分发、资产化  | 渠道健康度可控；内容资产沉淀进作品库 |

### 1.4 三条总军规

1. **先标签后流量，先转化后暴涨。** 顺序不可跳：没有清晰的标签，爆款流量来了也留不住（关注率低，且会带歪标签）。
2. **以复盘驱动迭代，而不是以情绪驱动。** 数据差 → 进入 §8 诊断流程；数据好 → 提炼结构复制（§4.1）。不因为单条扑街自我否定，也不因为单条爆了立刻全职。
3. **调性是一票否决项。** 起号期最容易为流量妥协调性（标题党、蹭热点、夸大）——本章程所有技巧都必须在 [DESIGN.md](./DESIGN.md) §5 调性规范内使用。

## 2. Phase 0：发布前准备（1–2 周）

> 目标：**建号即战备完毕**。账号装修、弹药库、对标结论、平台主阵地四件事全部落地后才发第一条。

### 2.1 定位校验（半天）

对照 [DESIGN.md](./DESIGN.md) §2 定位与 §3 受众，回答三个问题并写入 Console BrandProfile：

1. **一句话说清「我是谁 + 给谁 + 给什么」**（对齐 positioning 字段）；
2. **非目标受众明确吗？**（对齐 §3.3——不服务谁，决定你不做什么内容）；
3. **差异化检验**：目标用户能说出你与替代选择的区别吗？（对齐 §2.3 替代选择）。

### 2.2 对标调研（1–2 天）

找到 **5 个直接对标（同级/略高）+ 3 个榜样（头部）** 账号（含赛道内与你定位最接近的，见 [INTERVIEW_RESEARCH.md](../INTERVIEW_RESEARCH.md) §2 的赛道账号），用表格拆解：

| 拆解维度 | 问什么 |
|---|---|
| 定位与人设 | 一句话人设？粉丝凭什么记住 TA？ |
| 选题模式 | 常做什么主题？栏目化还是单发？重复度多高？ |
| 标题/封面公式 | 结构是什么？高频词？情绪方向？ |
| 内容结构 | 开头几秒怎么设计？中段节奏？结尾 CTA？ |
| 数据特征 | 播放均值/峰值？完播与互动大致表现？（新号用「赞/播放」粗估） |
| 变现路径 | 广告/带货/课程/私域？变现与内容的一致性？ |

**输出**：一张对标表 + 三条「可借鉴、不可照抄」结论（写在 §10 的 Phase 0 检查清单里）。注意：借鉴的是**结构**与**批量化能力**，不是选题与表达（调性红线）。

### 2.3 账号装修（半天，一次性做完）

按 [DESIGN.md](./DESIGN.md) §7.2 visualNotes 方向执行一套完整装修：

| 项 | 要求 | 对应字段 |
|---|---|---|
| 头像 | 真实生活照，非棚拍精修；各平台统一 | visualNotes |
| 昵称 | 品牌名直用（曹亚仑）；各平台统一 | handle |
| 简介 | 一行价值主张（对齐 positioning）+ 更新承诺（「每周田野记录」）+ 差异化钩子 | positioning |
| 背景/主页图 | 统一视觉系统（字体/配色） | visualNotes |
| 置顶内容 | 发布第一条后置顶「代表作或自我介绍」 | — |
| 主页一致性 | 从主页能 3 秒内回答「我是谁、给什么」 | — |

### 2.4 弹药库：30 天选题库存

- 按 [DESIGN.md](./DESIGN.md) §6.6 选题漏斗产出 ≥ **30 条**选题，**四支柱各 ≥ 5 条**（对齐 BrandPillar 覆盖）；
- 优先级排序（对齐 ContentItem.priority）：高 = 真实反馈 × 高普适；中 = 单点深入；低 = 过程记录；
- 每条选题带一行的「核心观点 + 一条证据/素材来源」——没有素材依据的选题直接在库里删掉（对齐「有依据」调性）。

> 弹药库的意义：起号期不该被「今天发什么」消耗意志力。子弹够，才有资格谈策略。

### 2.5 平台主阵地选择（半天）

**原则：主阵地 1 个（资源集中突破）+ 分发矩阵 2–3 个（一鱼多吃，零成本铺开）。**

选择主阵地的三个判据（按优先级）：

1. **目标受众在哪**：25–40 岁知识工作者、创作者、工程师 → B站/公众号/小红书/抖音都成立，按下面两条细化；
2. **内容形态与平台基因匹配度**：本品牌主线是「实拍田野长视频 + 深度拆解」→ 长视频平台（B站、视频号、公众号）优先；竖屏强钩子平台（抖音）做切片分发；
3. **算法对新号的友好度**：长尾型平台（B站/小红书/公众号）日更压力低于强推荐型平台（抖音），更适合个人产能。

各平台详细机制与打法见 §6。

### 2.6 设定 90 天目标（SMART）

模板（数值为建议量级，按自身基准调整）：

- **内容**：首发 90 天内发布 ≥ 12 条主内容（周更 1–2 条）+ 分发碎片 ≥ 24 条；
- **数据**：主阵地出现 ≥ 1 条「均值 5–10 倍」的内容；粉丝 ≥ 1000（B站/公众号/小红书经验线）；
- **能力**：完成 ≥ 4 轮周复盘，每轮沉淀 ≥ 1 条「下轮改什么」（对齐 reviewNote 的什么有效/下次改进）；
- **验证**：跑出 1 个「被验证的选题类型」和 1 个「被验证的标题/封面结构」。

## 3. Phase 1：冷启动期（0–90 天）

> 核心目标不是涨粉，而是**打标签 + 测反馈 + 建转化链**。90 天里你其实在跑一次低成本的产品测试。

### 3.1 打标签（垂直度）

- 前 90 天**只发主阵地垂类内容**，不蹭不相干热点（每个热点都问：它帮我强化标签吗？）；
- 发布时完整填写：话题标签（3–5 个，垂类词 + 人群词）、分类、关键词（对齐搜索收录，B站/小红书/公众号尤其重要）；
- 保持「人设一致」：所有内容放一起看，应该像同一个人的连续日记（对齐「我即品牌」）。

### 3.2 测反馈（每一条都是实验）

**一次只变一个变量**，其余全部按已沉淀的模板执行（标题/封面/首帧/结构）。建议排布：

- 同选题类型 × 不同表达角度（测试选题）；
- 同内容 × 不同标题/封面（测试打开率，§7.2/§7.3）；  
- 同结构 × 不同开头（测试 3 秒留存）。

> 不测就发 = 每次失败都不知道为什么。《A/B 测试是内容优化的核心工具》——每轮周复盘只统计"变量",不改口径。

### 3.3 发布节奏模板（建议）

| 周 | 主内容 | 分发碎片 | 目的 |
|---|---|---|---|
| 1–2 | 2 条 | 4–6 条 | 尽快让系统建模；验证发布流程 |
| 3–6 | 1–2 条/周 | 3–4 条/周 | 稳定供给；开始看周趋势 |
| 7–13 | 视数据调整：好的类型加产，差的类型减产 | 同左 | 产能向验证过的方向集中 |

> 起号期「频率 > 篇幅」：宁可一期 5 分钟的扎实内容，也别憋一个月做 40 分钟。**先证明你能持续，再证明你能做深。**

### 3.4 互动运营（数据信号的一部分）

- **每条发布后 1 小时内回复全部评论**（对齐「回访/纠错」机制，评论是免费的田野反馈）；
- 主动设计互动点：视频/图文结尾留「开放式问题」（对齐 §6.3 视频公式的互动环节）；
- 评论区出现高质量反对意见 → 置顶并认真回复（公开构建的信任资产，对齐 §8.3）；
- 私信被问到高频问题 → 记入选题库（评论即田野，对齐 §6.6 选题来源）。

### 3.5 冷启动期军规（Do / Don't）

**Do**

- 每条都带一条真素材（原话/数据/现场）；
- 固定发布时段与频率，让系统建立预期；
- 每 7 天做一次数据小复盘（§8.4），90 天做 4 轮完整复盘；  
- 正常看待前 10 条的数据波动——样本量太小，不构成结论。

**Don't**

- 不买粉、不互赞群、不刷量（刷出来的标签是毒标签，且毁灭账号信任）；
- 不因前 10 条数据差改定位或换赛道（至少给一个类型 5–8 条的机会）；
- 不追与垂类无关的热点；
- 不删「失败」内容（黑历史是公开构建的一部分，可置顶说明改进，不隐藏）；
- 不一天发 5 条（高频低质会稀释标签与主页转化）。

### 3.6 冷启动失败转向信号（3 个真实红灯）

1. **90 天无任何内容跑出均值 2 倍**（意味着选题或表达整体不在市场需求上——先转向选题方向，不是换平台）；
2. **有播放但涨粉率长期 < 观看的 0.5%**（主页转化坏了——修装修/简介/置顶，§2.3）；
3. **持续产出但均无明显反馈**（完播/互动全线平平）——检查是否太「自我表达」而非「提供可照做价值」（对齐定位的「可照做的系统」）。

红灯处理：进入 §8.5 诊断决策树，逐层排查，**一次只改一个杠杆**，再给 4–6 周观测。

## 4. Phase 2：成长期（90 天 – 6 个月）

> 目标：把 Phase 1 验证出的「少数有效模型」变成「稳定的平均线」。成功 = 均值抬升，不是赌单条。

### 4.1 爆款复制模型（复制结构，不复制内容）

1. **拆解**：拿到爆款后，用 §2.2 对标表的维度拆自己——是选题胜出（话题本身有传播势能）还是执行胜出（标题/封面/结构）？
2. **提炼**：沉淀成一张「已验证结构卡」：选题类型 + 标题公式 + 封面 + 内容骨架 + CTA（示例见 §7.2/§7.4）；
3. **换皮再创作**：用同一结构，换新的真实素材/对象/行业，**不重复用原素材**；
4. **测试边界**：同一结构连做 3 条，数据 2 好 1 差 → 结构有效；2 差 → 结构失效，回 §8.5。

### 4.2 系列化（从单发到栏目）

- 把被验证的选题类型升级为栏目（如「田野日志 00X」[INTERVIEW_PLAYBOOK.md](../INTERVIEW_PLAYBOOK.md) 的栏目体系做法）：
  - **给用户可预期**：看了一期，知道下一期什么时候来、长什么样（关注理由）；
  - **给算法连续样本**：同垂类连续内容加速标签固化；
  - 系列 ≠ 重复：每期要有「新的真实素材」（对齐田野调查标准流程 §6.2 的每行业 ≥ 3 位受访者）。

### 4.3 周复盘制度（§8 有模板）

- 固定每周一次 30 分钟复盘：本周数据 → 变量结论 → 下周动作；
- 每月一次完整复盘（对齐 reviewNote 汇总 + 渠道趋势）；
- 数据决策记录在 Console（reviewNote 字段），**结论要可追溯**：当时为什么这么判断、现在看对不对。

### 4.4 粉丝运营（私域承接）

- 粉丝画像校准：从评论区/私信抽样 10 条，对照 [DESIGN.md](./DESIGN.md) §3 受众画像，记录偏差；
- 建「核心粉丝」名单（并非私域群，而是内容共创）：催更、审稿、纠错、给选题——他们是最早的田野受访者池；
- 主页持续更新「代表作」，让新访客 3 秒内看到你最值得看的内容。

### 4.5 矩阵扩展（一鱼多吃正式化）

- 主阵地稳定（周更无压力 + 数据趋势向上）后，才按 [DESIGN.md](./DESIGN.md) §6.7 平台适配表逐平台铺开；
- 每个分发平台写清它的定位（对齐 PlatformChannel.positioning）与更新承诺（cadence）；
- 分发≠搬运：必须有平台化改编（§7.6），否则权重与体验双输。

## 5. Phase 3：稳定期（6 个月 +）

> 目标：从「账号」变成「渠道组合 + 内容资产 + 商业收入」的小系统。增长不再是第一性目标，**可持续与抗风险**才是。

### 5.1 供给与质量的平衡

- 固化产能节奏：批量制作（田野集中采集 → 分批剪辑发布），用库存平滑波动；
- 复盘从「周例行」升级为「季度战略」：定位/支柱/调性是否还成立（对齐 §9.3 季度校准）。

### 5.2 商业化（对齐 DESIGN.md §8.4 商业红线）

- 变现路径按「信任 > 变现」排序：先作品/出版物（沉淀资产），后商单、咨询、社群；
- 商业合作三问：真实用过吗？调性一致吗？敢公开说不好吗？——任何一问为否就拒；
- 每一步商业化都公开（build in public），接受观众监督。

### 5.3 反脆弱（账号资产化）

- **平台风险**：主阵地外的分发矩阵保持活跃（哪怕是低频率），避免单平台依赖；
- **内容资产化**：优质内容沉淀为作品库（Work，如出版物、App、Web App），从「内容」升级为「资产」；
- **人力弹性**：字段与流程（选题库→流水线→复盘）沉淀在 Console，任何一期断更不导致体系崩塌。

### 5.4 稳定期 KPI 转向

- 增长指标让位于：**回看率（90 天）/ 渠道健康度 / 复盘完成率 / 资产产出**（对齐 DESIGN.md §9.2 质量与结构层）。

## 6. 分平台机制与打法

> 通用框架在 §3–§4，本节只讲每个平台的**差异变量**。平台规则迭代快，本节为 2026-09 经验基准，上线前以平台官方为准；数值全部为经验区间，需 4 周数据自校准（§8.5）。

### 6.1 抖音（强推荐型 · 切片分发优先）

- **机制**：流量池递进（初始几百播放 → 数据达标进下一池）；核心信号 = 3 秒完播、整体完播、互动率；标签来自内容关键词 + 用户行为；
- **起号要点**：前 3 秒定生死（悬念/反常识/结果前置）；垂直度靠大量同主题内容堆出来；固定时段发布；自然流量冷启动对新人友好，但留存窗口极短；
- **本品牌适配**：主阵地**不做**（长视频实拍与强钩子基因冲突）；作为「切片 + 强钩子」分发平台（对齐 §6.7 平台适配表），把长视频的 1 个高光片段做成 30–60 秒口播切片；
- **参考健康线**：完播率（5 秒）≥ 60% 为佳（按视频长度递减）；赞/播放 ≥ 3%；评论/播放 ≥ 0.5%。

### 6.2 小红书（搜索 + 推荐双入口 · 图文/短内容优先）

- **机制**：标签匹配 + 搜索长尾双流量；「收藏率」权重市场公认最高（内容被反复使用=价值证明）；首页点击率由封面+标题决定；
- **起号要点**：选题 = 关键词（搜索即需求，用搜索联想词定选题）；封面大字 + 信息点明确；笔记结构「先结论后细节」；垂直标签从第一篇就开始打；评论运营小红书特有重要（种草区互动带笔记权重）；
- **本品牌适配**：适合「田野金句 + 干货图文」——把长视频里的原话/数据做成图文卡片（对齐 §6.7「原话金句 + 图文」）;
- **参考健康线**：收藏/播放 ≥ 3%（内容有价值）；赞藏比 ≈ 1:2 为佳；单篇生命周期长，发布 48h 后仍有长尾。

### 6.3 B站（社区型长视频 · 主阵地候选）

- **机制**：推荐 + 搜索 + 关注混合；数据信号 = 点击率、完播、三连（点赞/投币/收藏）、弹幕；**长尾极强**（老内容持续被搜到）；社区氛围：认真、反标题党、反感过度营销；
- **起号要点**：标题「信息点清晰 > 夸张钩子」（B站用户对标题党反弹大）；前 30 秒立住「这期给你什么」；弹幕要走心（内容结构里设计「弹幕点」）；互动区认真（B站粉丝粘性 = 真诚）；
- **本品牌适配**：**主阵地首选之一**——深度田野实拍长视频的主场；「真实 + 深度 + 第一性拆解」与社区口味高度匹配；与 [INTERVIEW_PLAYBOOK.md](../INTERVIEW_PLAYBOOK.md) 的栏目体系直接对接；
- **参考健康线**：点击率 5–10%（类型间差异大）；3 分钟以上视频完播 ≥ 30% 为佳；收藏比率是长效指标。

### 6.4 视频号（社交推荐型 · 私域联动）

- **机制**：核心是**朋友推荐**（朋友赞过 → 推给朋友的朋友）；微信生态（公众号/朋友圈/社群）是其天然分发渠道；完播与分享权重高；
- **起号要点**：冷启动靠**私域冷启动**——公众号读者、朋友圈、社群先转起来（朋友赞会触发社交推荐）；与公众号联动发布（阅读 1 次 = 视频曝光 1 次）；直播是视频号独特杠杆（订阅通知 + 私域沉淀）；
- **本品牌适配**：长视频双发（B站主版 + 视频号）并配公众号图文（对齐「长视频 + 转发语」）；直播可做「田野幕后/答疑」，与 build in public 天然契合；
- **参考健康线**：朋友推荐占比高的内容天然 10 倍级放大；分享率（分享/播放）是核心观察点。

### 6.5 公众号（私域 + 推荐混合 · 深度内容主场）

- **机制**：2023 后体系 = 关注（私域）+ 推荐（看一看）+ 搜索（搜一搜）三流量；打开率 = 铁粉浓度；
- **起号要点**：开头前两行定生死（折叠前就要给出「为什么值得读」）；合集/话题标签体系建全（长尾搜索入口）；定期更新培养打开习惯；留言区认真运营（公众号用户是私域化最高的用户群）；
- **本品牌适配**：**主阵地候选**——「完整方法论长文」与田野长文的主场（对齐 §6.7「完整方法论长文、结构完整可收藏」）；
- **参考健康线**：打开率 5–10% 为佳（个人号）；转发是放大关键；搜索流量占比逐步观察。

### 6.6 X（全球 build in public 社区）

- **机制**：算法信息流按互动排序；引用（quote）与回复权重高；话题标签已弱化；英文内容覆盖全球 tech 圈；
- **起号要点**：**过程帖 > 结果帖**（progress > results，与 build in public 完全同构）；Thread 连载（一主题拆 3–8 条）；固定发帖节奏（每天 1–2 条过程/数据/复盘）；多用数据与截图（真实性他证）；
- **本品牌适配**：英文过程帖（数据、进度、复盘片段，对齐 §6.7「过程帖/摘要」）；把田野与调教日志翻译/缩写为英文 thread，服务全球工程受众；
- **参考健康线**：赞/展现 1–3%；quote/回复率是硬信号；粉丝增长慢正常（价值在长尾与连接）。

### 6.7 平台组合建议（与 DESIGN.md §6.9 渠道角色一致）

| 角色 | 平台 | 频率建议 |
|---|---|---|
| 主阵地（深度长视频） | B站（首选，首选之一见 §6.3）+ 视频号双发 | 周更 1 条 |
| 图文沉淀 | 公众号 | 月度 2–4 篇（对齐 DESIGN.md §6.5 节奏） |
| 高频触达（切片/金句图文） | 抖音 + 小红书 | 随主内容发布 3–4 条/周 |
| 国际（过程帖/英文） | X / YouTube | 每周 3–5 条 |

> 原则：**主阵地先跑通，矩阵至少保持「自动分发 + 最小人工适配」的活跃度**（对齐 §6.8 MeOS 协同与渠道健康度）。

## 7. 内容工程：单条内容的合格线

> 每一条内容都按同一套流水线过，才能对比、才能迭代。这条流水线对应 Console 的 ContentItem 生命周期（idea → drafting → ready → published）。

### 7.1 选题（输入）

- 来源管道：田野所见、评论/私信（反馈即田野）、极致工程矛盾点、支柱补位、搜索词（小红书/公众号）；
- **筛选四问**（对齐 DESIGN.md §6.6，全部通过才立项）：
  1. 有真实反馈可验证吗？
  2. 能拆到第一性吗？
  3. 观众能照做吗？
  4. 符合接近真实/接地气/有依据吗？
- 一条选题必须有「核心观点 + 一条素材证据」才能进入 drafting（对齐 §2.4）。

### 7.2 标题公式库（对齐 §5.6 禁用词）

| 公式 | 结构 | 示例（本品牌风格） |
|---|---|---|
| 结果前置 | 「我去 X 做了 Y，结果…… 」 | 「我去外卖站蹲了三天，算清了一单到底赚几块」 |
| 反直觉 | 「我以为…… 直到……」 | 「我以为 AI 能降本，直到亲眼看见生产线怎么用它」 |
| 数字承诺 | 「N 个 X 里，只有一个…… 」 | 「三个修车师傅里，只有一个靠手艺赚钱」 |
| 悬念留白 | 「X 告诉我一句大实话」 | 「跑船 20 年的大副，跟我说了句大实话」 |
| 第一性提问 | 「为什么 X 都做不好 Y？」 | 「为什么人人都说要做 IP，却没人说得清？」 |

- 规则：真实 > 夸张；具体 > 抽象；禁用词清单严格执行（DESIGN.md §5.4/§5.6）。

### 7.3 封面 / 首帧工程

- 视频首帧 = 标题的视觉版：大字 + 现场感画面，3 秒内可读（对齐 §7.2 视觉方向「现场实拍 + 大字标题」）；
- 封面统一字体/构图系统（对齐 visualNotes）；
- 图文书目（小红书/公众号）：封面即「目录预告」，信息点 ≥ 1 个明确价值。

### 7.4 内容结构模板

**视频（长）**（对齐 DESIGN.md §6.3 公式）：

1. 钩子（真实问题/反直觉发现，≤ 15 秒，不夸张）→
2. 现场（实拍 + 原声，建立身临其境）→
3. 真实反馈（原话上屏，先给「人」再给「理」）→
4. 第一性拆解（为什么是这样，讲清因果）→
5. 落地（观众能照做的一步）→
6. 互动（一个问题，请观众给反馈——反馈本身也是田野）。

**图文（长文）**：开头 2 行给「读完得到什么」→ 结构用层级标题（可跳读）→ 每个论点配一条证据 → 结尾给行动清单。

**短内容（切片/帖）**：前 3 秒给结论 → 30 秒内一个完整信息单元 → 结尾一个互动钩子。

### 7.5 发布环节

- 固定时段：按平台用户活跃窗口发布（B站/公众号晚间为主；小红书工作日午晚；X 北京时间晚间 + 美东早间两发）；
- 话题标签 3–5 个：垂类词 + 人群词 + 1 个栏目词（对齐栏目化）；
- 发布后 1 小时内：主回复评论、主动在评论区补一条「补充信息/发起讨论」（提高互动密度）。

### 7.6 一鱼多吃的平台化改编（不是搬运）

| 源内容 | 平台化改造 |
|---|---|
| 长视频 | B站/视频号：仅改名与封面；抖音：剪 30–60 秒切片，重写钩子；小红书：金句图文卡；公众号：整理成方法论长文；X：数据/过程 thread |
| 判断标准 | 改完的内容「换平台也成立」；标题按 §7.2 每平台重写（对齐 ContentDistribution.adaptedTitle） |

## 8. 指标体系与复盘闭环（核心）

> 口径与 Mac Console 的 MetricSnapshot 对齐：**followers = 累计，views/likes/comments/shares = 本周期增量**。所有基准为经验区间，**发布 4 周后以自身数据重新校准**（§8.5），平台规则变动时回到官方读数。

### 8.1 内容级指标（每条内容都记）

| 指标 | 定义 | 它回答什么 |
|---|---|---|
| 曝光/播放 | 推荐+搜索+主页 | 流量池大小 |
| 前 3 秒留存 / 5 秒完播 | 开头留存率 | 钩子质量 |
| 完播率 | 看完比例（长视频分段看） | 内容密度与结构 |
| 吐槽率（可选） | 快速滑走的位置分布 | 哪段在掉人 |
| 赞/播放 | 认可率 | 价值密度 |
| 收藏/播放 | 收藏率 | 可复用价值（长效指标） |
| 评论/播放 | 互动率 | 讨论度（含评论质量） |
| 转发/播放 | 分享率 | 传播意愿 |
| 涨粉率 | 新增粉丝/播放 | 转化链效率 |
| 主页转化 | 主页访问/观看 | 主页装修与简介效率 |

### 8.2 渠道级指标（每周记一次快照）

- 粉丝（累计）、周增粉、周播放增量、周互动增量、周收入（如有）——对应 MetricSnapshot 字段。

### 8.3 参考健康线（经验区间，需自校准）

| 指标 | 健康参考（长视频为主） | 说明 |
|---|---|---|
| 完播率（中长视频） | ≥ 30% | 5 分钟以上的霸道内容可更高 |
| 赞/播放 | ≥ 3% | 分发切片类更高 |
| 收藏/播放 | ≥ 3% | 小红书 ≥ 3% 为佳 |
| 评论/播放 | ≥ 0.5% | 强互动设计可到 1%+ |
| 涨粉率 | ≥ 0.5–1% | 低于 0.5% 查主页转化 |
| 爆款阈值 | ≥ 均值 5 倍 | 进入 §4.1 复制流程 |

> 注意：这些是行业通行经验区间，不同平台/题材差异可达数倍。**你的基准 = 你的 4 周滚动均值**，本表只用于起步参照。

### 8.4 复盘模板（复用：每期 / 每周 / 月度）

**单期 reviewNote**（对每条发布内容，发布后 3–7 天填）：

1. 数据：播放 / 完播 / 赞 / 藏 / 评 / 转 / 涨粉；
2. 什么有效（可复用的东西：选题类型？标题公式？结构段？）；
3. 下次改进（明确到「下一期做什么」的一条动作）；
4. 评论洞察（3 条最有信息量的评论摘录——它们就是田野）。

**每周复盘**（30 分钟，对齐 Phase 2 制度）：

- 本周变量实验结论（§3.2 测了什么？）；
- 产能与节奏是否达标；
- 下周 1 个实验变量 + 1 个改进动作。

**月度复盘**（对齐 MetricSnapshot 趋势）：

- 渠道趋势（粉丝曲线、播放曲线——Console 总览图）；
- 支柱覆盖统计（哪支柱缺位？）；
- 标签自查（新粉丝画像与 §3.1 受众的偏差）；
- 商业/资产进展（作品库、合作邀约）。

### 8.5 数据诊断决策树（数据差时按序排查）

```
单条/阶段数据不达标
├─ 曝光低（播放少）
│   ├─ 开了多少条样本？< 5 条 → 继续供给，先攒样本（别下结论）
│   ├─ 标题/封面点击率问题 → 换公式再测（§7.2/§7.3，一次变一个）
│   └─ 标签混乱/垂类漂移 → 收紧选题，维持标签一致性 2–4 周
├─ 曝光正常但完播差
│   ├─ 开头掉人快 → 重写钩子/首帧（§7.4 第 1 段）
│   ├─ 中段掉人 → 砍冗余（一条内容只留一个核心信息）
│   └─ 节奏问题 → 对照对标账号结构（§2.2 表格）
├─ 完播好但互动差
│   ├─ 没设计互动点 → 结尾明确提问（§7.4 第 6 段）
│   └─ 话题无讨论空间 → 选题回到「真实反馈 × 高普适」（§7.1 筛选四问）
└─ 互动好但涨粉差
    ├─ 主页转化坏 → 修头像/简介/置顶（§2.3）
    └─ 内容「值得看但无法定义你」→ 强化人设一致性，把定位写进简介与固定开场
```

**一条原则：一次诊断只改一个杠杆，改完给 4–6 周（≥ 4 条内容）再评判。**

## 10. 90 天执行 SOP（周历模板）

> 将 90 天拆成 3 个 30 天，每个 30 天有主题。模板可直接落到 Console：选题入 ContentItem（idea → ready），发布记 ContentDistribution，每周快照进 MetricSnapshot，复盘写 reviewNote。

### 第 1–30 天：定位与标签（多发、快测）

- 每周 2 条主内容 + 4 条分发碎片（切片/图文/帖）；
- 每 2 条换一次标题/封面变量实验（§3.2）；
- 第 14 天：核对 Phase 0 目标 —— 主题是否聚焦、栏目是否成立；
- 第 30 天：首次月度复盘（§8.4）。

### 第 31–60 天：验证与聚焦

- 每周 1–2 条主内容；产能向表现好的类型倾斜（§4.1）；
- 开始系列化（给表现好的题型起栏目名，固定开场/片尾）；
- 第 60 天：标签自查（粉丝画像）、主页转化率检查。

### 第 61–90 天：复制与固化

- 固化为「已验证结构卡」≥ 2 张（§4.1）；
- 主阵地周更节奏无压力 → 启动矩阵分发细则（§6.7）；
- 第 90 天：完整复盘 —— 目标对照（§2.6）、支柱覆盖、90 天趋势、下阶段计划（Phase 2 或转向诊断）。

### 每周围绕同一检查清单运转

- [ ] 本周发布 ≥ 计划条数，全部走完内容流水线（选题四问 → 制作 → 预发布检查[DESIGN.md §9.4] → 发布 → 复盘）；
- [ ] 每条发布 1 小时内回复评论；
- [ ] 记录内容级数据（§8.1）到 ContentDistribution；
- [ ] 每周快照（§8.2）进 MetricSnapshot；
- [ ] 周复盘 30 分钟，结论写 reviewNote；
- [ ] 评论/私信高价值反馈 ≥ 1 条入选题库。

## 11. 与 Brand Console 的对应（字段映射）
