# 06 — 指标体系（Metrics & Measurement)

> 回答「怎么知道打得对不对」。现状：**仓库零埋点**，本分册一半是指标定义，一半是补齐测量能力的计划。

---

## 一、北极星指标

> **每周至少完成一次「数据汇入 + 反思」闭环的活跃实例数（周闭环实例数）**

- 为什么不是 star/下载：那是虚荣指标（vanity metrics），G2 gate 明确以留存为准
- 为什么是这个闭环：同时验证 MeLog（数据汇入）与五维（反思习惯）两大核心价值，是留存的最佳先导
- 当前测量的诚实说明：自托管 + 无埋点 ⇒ 无法直接观测，Phase 0–1 用代理指标，Phase 0 上线 opt-in 匿名 ping 后逐步过渡

## 二、漏斗与各环节测量

| 漏斗环节 | 定义 | 测量方式（当前 → 补齐后） |
|---|---|---|
| 触达 | 看到内容 | 各平台数据后台 → 短链点击数 |
| 兴趣 | 访问 GitHub/Landing | GitHub Traffic（Insights）+ Landing PV |
| 安装 | clone / docker run | clone 数（GitHub）→ opt-in ping 的 install 事件 |
| 激活（aha） | 完成「1 数据源 + 1 次反思」 | ⬜ 无 → opt-in 匿名事件（不发内容，只发计数） |
| 留存 | 次周/30 日闭环 | ⬜ 无 → 同上（周粒度） |
| 推荐 | 分享物转发 / 邀请 | 分享按钮事件 + 邀请码（P2） |
| 收入（P4） | waitlist → 付费 | Landing waitlist 表 → 订阅后台 |

## 四、测量能力补齐计划（Phase 0 必做）

原则：**opt-in、匿名、只发计数不发内容**，与「数据主权」定位完全一致——我们连自己的统计都做成可关闭的。

| 项 | 方案 |
|---|---|
| install ping | 首次启动时征询 opt-in；每周一次 POST 计数（随机 ID + 版本号 + 平台），无任何业务数据 |
| 激活/留存事件 | 同通道发 `activated` / `weekly_active` 计数；面板用现成 SaaS 或一张 SQLite 表 |
| Landing 归因 | 唯一短链服务 + UTM 规范（04 分册） |
| 定性指标 | 用户访谈记录库（docs/interviews/ 或 Notion），每月汇总 JTBD 修正回 02 分册 |

## 五、复盘节奏

| 节奏 | 内容 |
|---|---|
| 每周一 30 分钟 | 漏斗周报（哪怕数据是代理指标），标记异常 |
| 每月 1 次 | KPI 对照表 + 一次用户访谈主题复盘，更新各分册「假设」值 |
| 每 Gate | 按 [05 分册 §四](./05-launch-plan.md) 执行 pass/回炉决策，结果登记进总纲变更记录 |
| 红线 | 连续 2 周北极星（或其代理）下降 → 冻结新功能开发一周，只做留存归因 |
