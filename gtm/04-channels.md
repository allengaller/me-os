## 二、核心增长循环（Loops）

产品驱动增长的三个自增强循环，比单点渠道更重要：

### Loop 1 · 内容飞轮（启动最快）
```
写代码/做产品 → 拆成 build log 内容 → 带来 GitHub 访客
     ↑                                      ↓
产品反馈成为下期素材   ←   用户 issue/PR/讨论
```
- 节奏：每周 1 条主内容 + 2–3 条轻量动态（即刻/小红书）
- 素材库：git 历史、DESIGN.md 架构图、MeLog 技能报告截图、翻车与修复
- 已有资产：品牌板块的 [OPERATIONS.md](../docs/实践/品牌/运营.md)（生产 SOP）与 [COPY.md](../docs/实践/品牌/文案.md)（话术模板）直接复用

### Loop 2 · 分享物裂变（P2 上线）
- 平衡轮雷达图海报（带 MeOS 水印与链接）—— 用户晒人生状态即传播
- 年度个人数据报告（「你的 2026：睡眠 X 小时、Y 条洞察、Z 次复盘」）—— 年终低成本刷屏物
- MeLog 技能报告的「分享为图片」按钮
- 原则：默认手动触发、脱敏模板、水印克制（不做人设化 sticker 轰炸）

### Loop 3 · 生态飞轮（P3 启动）
```
MeLog Standard 文档 → 开发者写连接器/技能 → 覆盖更多数据源
        ↑                                        ↓
   标准更完善  ←  第三方场景反哺产品需求
```
- 关键动作：连接器开发指南、`melog-connector` 脚手架、生态目录页（GitHub README 生态区）
- 标杆合作：找 2–3 个真实场景（如 Obsidian 同步插件、运动手表导出工具）做到官方级示例

## 三、按画像的渠道 × 信息匹配

| 画像 | 首选渠道 | 传递的信息（来自 01 分册信息屋） |
|---|---|---|
| AI 尝鲜者 | Show HN / V2EX / MCP 目录 | 支柱 2：AI 原生 ——「MCP 直接读你的生活数据」 |
| 生产力极客 | 少数派 / 小红书效率区 / B 站 | 支柱 1+3：数据主权 + 方法论内置 |
| 知识工作者 | 创始人自有渠道 | 整体故事：「我用它经营我的品牌」 |

## 四、首批实验（Phase 0–1，各一个最小验证）

| 实验 | 假设 | 最小动作 | 判定 |
|---|---|---|---|
| 内容飞轮 | TA 想看个人项目从 0 到 1 | 连发 4 周 build log，第 4 周看主页→GitHub 点击率 | 点击率 ≥ 2% 则加频 |
| Show HN 首发 | 「local-first + MCP」在 HN 有话题性 | 周二–周四上午（美西）发帖，准备 48 小时蹲守回复 | 首页停留即成功 |
| 分享物 | 用户愿意晒平衡轮 | 手动给前 20 个内测用户生成海报，观察自发转发率 | ≥ 5 人自发发布则进 P2 正式开发 |
| 生态钩子 | 有开发者愿意写连接器 | Discord/Discussions 发连接器挑战（sample + 奖励为 Founder Edition） | ≥ 3 个提交即启动 P3 前置 |
